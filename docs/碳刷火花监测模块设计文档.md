## 一、检测原理：物理信号路线（零训练样本）

### 1.1 相机前置设置：曝光与增益定死

* **关闭自动曝光（AE)、自动增益（AGC)、自动白平衡（AWB)**，把曝光时间与增益固定在一个定值；
* 定值的选取原则：正常运行画面下接触区不饱和、画面整体不过暗，饱和只应在真正出现火花时发生；
* 锁定的曝光/增益值写入 `spark_config.json` 存档，作为基线环境的一部分；
* 若现场相机不支持手动锁定，需另行处理（见第六章核实项）。

> 原因：自动曝光会在火花出现瞬间整体压暗画面，把"局部过曝亮斑"信号淹没，必须定死。

### 1.2 空间划区：三类 ROI（标定大屏画框，套水流标定套路）

| ROI | 位置 | 作用 |
| :--- | :--- | :--- |
| **接触区 ROI** | 碳刷与滑环贴合的切线狭长带 | 主信号 + 确认信号 + 颜色签名采集区 |
| **参考区 ROI** | 与接触区同视场、同材质的静止背景（如刷握金属支架） | 提供"正常亮度基准"，做相对量计分 |
| **下落区 ROI** | 接触点正下方的区域 | 火星坠落亮点计数，做严重度分级 |

### 1.3 四路物理信号

1. **主信号 —— 接触区过曝亮斑**：转 HSV 后，V 通道 ≥ 饱和阈值（如 `V ≥ 240`，可调）的像素计数与占比；
2. **确认信号 —— 接触带亮度闪烁**：接触区 V 通道均值（或饱和像素数）的帧间波动，火花表现为高频闪烁而非恒定亮斑；
3. **防误报 —— 颜色签名**：
   * 电弧为**蓝白色**：高 V、低/中 S、H 落在蓝紫区间（OpenCV H∈[0,179]，约 100~130，现场微调）；
   * 碳刷高温/磨损火花为**橙黄色**：H 约 5~25 区间；
   * 阳光漫反射为全谱高亮、S 低但 H 分布宽，与上述签名不符，予以剔除；
4. **分级信号 —— 下落区亮点**：接触点下方下落区内的亮点计数，反映火星坠落规模，用于严重度分级（仅接触区亮斑 = 轻度疑似；伴随下落亮点 = 重度）。

### 1.4 计分口径：相对量

所有计分均用**接触区相对参考区的相对量**，消除整体光照漂移（昼夜、云影、灯光变化）：

```text
相对饱和率 = 接触区饱和像素占比 − 参考区饱和像素占比      ← 主信号计分
相对闪烁   = 接触区帧间亮度波动 − 参考区帧间亮度波动        ← 确认信号计分
```

### 1.5 判决链

```text
主信号(相对饱和率超阈) ∧ 确认信号(闪烁超阈) ∧ 颜色签名命中(蓝白/橙黄)
        │
        ▼
时序确认（持续时长口径待项目主确认，见第六章）
        │
        ▼
输出：疑似 / 告警，并附下落区亮点数给出的严重度分级
```

## 二、阈值标定：正常基线法 + 慢线趋势（不用火花样本）

### 2.1 正常运行录像采基线

* 采集**正常运行**录像（建议覆盖昼夜、不同负荷，累计若干小时），离线统计各指标的正常分布；
* 统计对象：相对饱和率、相对闪烁、下落区亮点数、颜色签名命中数的均值 / 标准差 / 分位数。

### 2.2 阈值立在正常分布之外

* 各信号阈值取 `mean + k·σ`（建议 k = 5~6）或高分位数（如 P99.9)，确保正常工况几乎不可能触碰；
* 阈值写入 `spark_config.json` 持久化，支持 Web 端热更新（沿用水流模块 `/api/update_params` 的思路）。

### 2.3 慢线：亚阈值疑似闪烁逐日计数画趋势

* 每个"亚阈值但接近阈值"的疑似闪烁事件计入当日计数，逐日累计并画趋势（落盘为 CSV/JSON，Web 大屏可展示）；
* **频次抬头**（如连续 N 天环比上升、或日计数超过基线均值 + kσ）即发飞书**预警提示**（不触发继电器）；
* 目的：捕捉"火花从无到有"的早期苗头——真火花出现前往往先有疑似闪烁频次抬头。

## 三、验证方法：人工造火花三档

| 档位 | 方法 | 验证目的 |
| :--- | :--- | :--- |
| **1. 合成注入** | 把火花光效按**加色混合**（per-channel 像素值叠加后截断到 255) 贴进真实正常录像，生成考卷集 | 只测**灵敏度下限**：阈值附近的微弱火花能否被检出 |
| **2. 公开真实打火视频离线当考卷** | 收集公开的碳刷/滑环/电机打火**真实**视频（必须核验来源、排除 AI 生成），离线回放跑全链路算法 | 统计检出率与误报率，作为离线考试成绩 |
| **3. 现场实物模拟** | 检修窗口在刷握附近用**角磨机或电焊**人为造火花 | 走通 **相机 → Jetson 检测 → 飞书卡片 → 继电器 Y1** 的真实联动链路（验证的是联动，不是算法灵敏度） |

**验收口径**：**模拟火花必检出 + 误报率达标**。不承诺对"从未发生过的真实火花"的检出率——因为没有真实正样本可供校准，任何对真实火花检出率的承诺都无依据。

## 四、上线策略：先按记录仪口径跑一期

* **灵敏度拉高**（宁可误报、不漏报）：阈值先按第二章的宽松端取；
* **触发只做两件事**：保存触发点前后片段录像（如 ±10 秒，落盘 `spark/recordings/`)，并向飞书群发**"疑似火花"提示卡片**（字段沿用 `alarm_py/feishu_alarm.py` 的 `notify_spark_alarm`：故障部位、置信度、持续毫秒、处置建议）；
* **一期不直连继电器跳闸**：Y1 虽已预留给火花，但一期只在日志和 `/api/status` 里记录"若直连本应动作"，不真吸合；
* 跑一段时间（建议 ≥ 2 周）**摸实误报率**，据此收紧阈值；
* 误报率达标后，由项目主决策是否把 Y1 正式接入碳刷保护跳闸回路（二期决策点，届时飞书卡片由"疑似提示"升级为红底紧急卡）。

## 五、架构：套水流模块的实现套路

### 5.1 目录与配置

```text
spark/
├── 📁 src/                 # 火花检测 C++ 源码（新建）
├── 📁 images/              # 碳刷实景、验证快照
├── 📁 videos/              # 正常运行基线录像、考卷视频（预留）
├── 📁 recordings/          # 触发片段录像落盘目录（预留）
├── ⚙️ spark_config.json    # 配置（仿 water_config.json 结构）
└── 📑 README.md
```

`spark_config.json` 建议字段：

| 字段 | 说明 |
| :--- | :--- |
| `contact_roi` / `reference_roi` / `falling_roi` | 三类 ROI `[x1,y1,x2,y2]`，标定大屏画框写入 |
| `camera` | 锁定的曝光时间 / 增益值（定死，存档） |
| `v_sat_threshold` | V 饱和阈值（如 240) |
| `hue_blue_white` / `hue_orange_yellow` | 颜色签名 H 区间 |
| `use_relative` | 是否启用相对量计分（默认 true) |
| `thresholds` | 各信号阈值（正常基线法标定，见第二章） |
| `confirm_duration_ms` | 时序确认口径（待项目主确认，见第六章） |
| `level_thresholds` | 下落区亮点数分级阈值 |
| `record_pre_sec` / `record_post_sec` | 触发录像前后片段长度 |
| `trend` | 慢线：日计数文件路径、预警倍数 k、连续天数 N |
| `relay_channel` | 固定 1（Y1)，`relay_trip_enabled: false`（一期不直连跳闸） |
| `feishu` | 飞书凭证与大屏跳转 URL（复用水流配置块） |
| `cooldown_sec` | 告警冷却（防轰炸） |

### 5.2 复用清单（直接套水流模块成品）

| 能力 | 复用来源 |
| :--- | :--- |
| 标定大屏（鼠标画框绑定 ROI、锚点、保存持久化） | `water/src/test/calibrate_studio.html` + Web Studio 模式（三类 ROI 按接触区/参考区/下落区绑定） |
| 配置 JSON 持久化 + 热更新 API | `water_config.json` 模式 + `/api/status`、`/api/update_params` 类接口 |
| 飞书客户端 | `water/src/feishu_client.{h,cpp}`，新增 `send_spark_suspect_async`（一期"疑似"卡）等方法，字段参考 `alarm_py/feishu_alarm.py:314` 的 `notify_spark_alarm` |
| 继电器客户端 | `water/src/relay_client.{h,cpp}`，火花固定通道 1（Y1)，一期 `relay_trip_enabled=false` |
| 视频拉流 | GStreamer NVDEC 管线（`rtspsrc → rtph265depay → nvv4l2decoder → appsink`)，`env_utils.h` 读 `.env` |
| Web 推流与前端 | MJPEG `/video_feed` + Canvas 叠加层 + 60s 内存微回收 |
| 运维规范 | 板端全部在 `agent_work` tmux 会话；一键 `run_spark.sh`（仿 `run_analyzer.sh`) |

### 5.3 进程形态

两种候选，**待项目主确认（见第六章）**：

* **独立进程**：`spark/src/` 独立服务，Web 端口避开水流的 8080（建议 8081)，目录结构完全自洽；
* **并入水流服务**：作为 `water_flow_analyzer` 同进程内的第二业务模块（多 ROI 多状态机复用），共享 8080 大屏和飞书/继电器客户端。

### 5.4 二期（本期不实现）

* **PatchCore 一类"只学正常"的特征距离异常检测**作为第二投票通道（与物理信号路线做投票融合），只需正常录像即可训练，与一期路线互补；需先在板端验证开销，排入二期；
* `yolov8_trt_engine/` 保留为公共推理底座（二期异常检测可复用其 CNN 特征提取），但一期火花检测不走 YOLO。

## 六、待项目主确认清单（本设计不自行拍板）

## 七、开发里程碑建议

1. **M1 基线采集**：锁定相机曝光/增益 → 录正常运行录像 → 离线跑第二章基线统计 → 生成 `spark_config.json` 初版阈值；
2. **M2 离线验证**：合成注入 + 公开真实打火视频两档考卷跑通，输出灵敏度/误报率报告；
3. **M3 单机联调**：标定大屏画三类 ROI → 本地/工位仿真触发 → 飞书"疑似"卡 + 片段录像落盘；
4. **M4 现场真链路**：检修窗口角磨机/电焊造火花，走通相机→检测→飞书→Y1（联调脉冲）全链路；
5. **M5 记录仪上线**：一期口径跑 ≥2 周，统计误报率、画慢线趋势，回收阈值；
6. **M6 决策点**：误报率达标后，项目主决定 Y1 接跳闸 + 升级红底紧急卡；二期再评估 PatchCore 第二投票通道。
