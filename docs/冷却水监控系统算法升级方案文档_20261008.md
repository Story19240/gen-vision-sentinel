## 1. 现状算法全解：系统到底在测什么

### 1.1 正式版定位澄清

**`water/src/test/water_flow_analyzer.cpp` 是唯一正式交付版**（内部代号 Analyzer），集成了 GStreamer NVDEC 硬件解码、动能积分、三级状态机、AnchorTracker 抗抖、MJPEG Web 大屏、`/calibrate` 在线标定、`/cutoff` 断水演练与飞书异步告警全链路。

`water/src/water_monitor_server.cpp` + `water_flow_detector.cpp` 为**早期骨架版本**，仅作历史参考，不再演进。注意：`water/README.md` 与 `water/src/README.md` 目前仍沿用旧定位描述（把 `test/` 称作"测试与标定专属目录"），已列入待修正项，避免误导接手者。

### 1.2 能量值 E 的完整定义

系统每帧为每根水管计算一个标量 **E（能量值）**，其本质是：**ROI 区域内，两帧之间发生明显变化的像素，占 ROI 总像素数的百分比**。它与物理学动能（1/2 mv^2）无关，"动能"为工程命名。

计算链路（`water_flow_analyzer.cpp` 的 `process()`）：

```text
彩色帧 → 转灰度 → 5x5 高斯模糊 → 与"上一帧" absdiff 逐像素求差
        │
        ▼
差值 > 12 的像素置白(255)，其余置黑(0)        ←→ 二值化帧差掩码
        │
        ▼
某根管 ROI 内：数白色像素个数 active
        │
        ▼
E瞬时 = (active / ROI总像素数) x 100            ←→ 能量百分比 (0~100)
        │
        ▼
E = 0.75 x E瞬时 + 0.25 x E历史                 ←→ EMA 指数平滑，滤除单帧毛刺
```

**具体示例**：1 号管 ROI 为 160x170 = 27200 像素，若某帧有 1500 个像素发生明显变化，则 E ≈ 1500 / 27200 x 100 ≈ **5.5**。

### 1.3 为什么这个值能代表"有没有水"

帧差掩码的天然特性：**静止物体在帧差图里是全黑的**（水泥壁、铁管、螺栓两帧之间零变化），只有**流动水花、跳动的反光**会持续产生像素闪烁。因此：

| 现场工况 | E 的表现 |
| :--- | :--- |
| 正常出水 | ROI 内水花翻滚，E 稳定在阈值以上（现场实测粗管可达 20，贴壁细流约 6） |
| 断水停流 | 水柱消失，ROI 回归静止墙面，E 瞬间趋近 0 |
| 气阻/波动 | 水柱一时变细变弱，E 跌破阈值但很快拉回 |

### 1.4 三级状态机（正式版判定规则）

每根水管独立运行状态机，判定链条 **唯一依赖 E 值**：

| 条件 | 状态 | 表现 |
| :--- | :--- | :--- |
| E ≥ 阈值 | NORMAL | 绿框 |
| E < 阈值 持续 0.5 ~ 2.0 秒 | WARN | 橙框（疑似气阻波动，不告警） |
| **E < 阈值 持续 ≥ 2.0 秒** | **ALARM** | 红框 + 飞书红底卡片 + 继电器通道预留联动 |
| E 回到阈值以上 | 立即回 NORMAL | 若为 ALARM 恢复，推飞书绿底卡片 |

**防误报三重保险**：开机 **8 秒静音预热期**（杜绝黑屏解码期五管并发误报）、单管报警后 **60 秒推送冷却**、仅状态**跃迁**瞬间推送（滞留期间不重复轰炸）。

各管阈值按现场实测水势标定（`water_config.json`）：1 号粗管 4.0，2/3/4 号 3.5，5 号贴壁细流 2.5。

## 2. 核心结论：能不能"分析水量大小"？

**能定性，不能定量。**

- **定性可行**：E 与"水势强弱"正相关——水大水花翻滚则运动像素多，水小则少；配置里 5 根管差异化的阈值正是这一事实的实测体现；
- **定量不可行**：E 不是升/分钟级流量，不做体积换算，且受光照、ROI 位置、水花形态影响很大。定位是"**相对水势监测哨兵**"，不是流量计；
- **固有局限**：它测的是"动得欢不欢"——平顺流动、反光恰好不动时 E 偏低；小水但溅射欢时 E 偏高。适合"通流/断流"二值判断；要精细分档水量需现场实测各水位对应 E 值后细化阈值（或走第 5.3 节 CNN 路线直接做语义分级）。

## 3. 方案可行性评估

### 3.1 结论：这套方案是对的，值得保留

业务本质是二值判断（断流 = 重大事故），帧差能量法恰好最契合：零训练数据、零模型漂移、单帧 0.05ms 级开销、与火花检测共享算力时互不挤压。配套的 2 秒确认、8 秒预热、60 秒冷却体现了"误报比漏报更烧钱"的工业正确观念。**对"单管断流即报警"这一需求：够用、可靠、好维护。**

### 3.2 三大已知软肋

1. **怕"假静止"（流冻结）**：RTSP 卡死 / 解码丢帧 / 摄像头冻结 → 帧差全零 → E 归零，与真断水完全同形。届时 5 根管**同时**报警，半个 fail-safe（暴露传感器故障），但现场分不清"五管真断水"还是"摄像头死了"；
2. **怕相机自动曝光 / 日夜切换**：固定阈值 12 建立在光照稳定前提上，AE 调增益快门导致底噪漂移，阈值失效（详见第 4 节对策）；
3. **不认识"向下"**：水最有辨识度的特征是**持续向下运动**，帧差只知道"哪里动了"。水平振动、人影扫过同样能喂出能量值（当前靠锚点抗抖 + 2 秒确认对冲，属于治标）。

## 4. 夜间 IR 黑白模式适配分析

### 4.1 结论：能用，原理上零障碍，甚至可能更稳

算法第一步 `cvtColor(BGR2GRAY)` 进门即丢弃颜色——IR 黑白画面与彩色转灰度后是同一种形态，算法完全无感。且：

- **水在 IR 下依然高度可见**：流动水花对红外光有强镜面反光，IR 补光灯近距离照射下水柱呈高亮区，反差清晰；
- **昼夜切换瞬间自愈**：IR cut 切换引起的全图跳变仅持续毫秒级，EMA + 2 秒确认直接滤除，状态机不会翻转；
- **最坏退化形态安全**：AE/光照突变的影响最多持续数百毫秒，而报警需持续 2 秒低迷——最坏情况是 WARN 闪一下自行恢复，不会炸群。

### 4.2 夜间真正的问题：高增益传感器噪声

夜间增益拉高 → 帧差底噪整体上浮 → 能量基线漂移。影响最大的是贴着阈值 2.5 跑的 5 号贴壁细流。对策见 5.1 节。

## 5. 升级路线（按性价比排序）

### 5.1 路线一【半天见效，先做】低成本立竿见影包

#### 5.1.1 相机参数锁定 + 恒定照明（零代码最强招）

无人值守工业监控通用原则：**不让镜头自己思考**。

- 海康摄像头网页配置中，将**自动曝光、自动增益、自动白平衡全部锁为手动固定值**；
- 摄像头旁加装一盏小补光灯常开（或强制始终 IR 模式），使"白天"与"夜晚"在算法眼里同形；
- 固定场景 + 固定光照 + 固定曝光 = 帧差天堂模式，现有阈值长期免调。**此招可解决约 80% 的环境干扰问题。**

#### 5.1.2 噪声地板自适应阈值（代码兜底）

不锁参数也能救，思路：**让阈值追着底噪走，而不是写死 12**。

- 每帧顺带计算一块"静物参考区"（画面角落永远静止的水泥墙）的帧差强度中位数，作为当帧噪声地板 `N`；
- 二值化阈值动态设为 `max(12, k x N)`：白天 N 小维持 12，夜间增益拉满 N 上浮则阈值自动跟随；
- 改动量：`process()` 内约 10 行代码。

#### 5.1.3 全局流冻结 / 信号异常检测

以 ROI **之外**的画面区域每帧计算全局帧差能量：若全局能量同样趋零 → 判定为"**视频流冻结/信号异常**"，单独报一类警，与真实断水区分，杜绝"摄像头死了假装五管断水"。

#### 5.1.4 阈值自动标定

启动时先采集 30 秒健康值，取基线的 30% 作为各管阈值自动落盘。机器换人/换摄像头后无需手工调参。

#### 5.1.5 （可选）昼夜双参数组

能量计算前检测全图平均亮度，低于设定值即切换"夜间参数组"（如二值化阈值 12 → 18）。前两招落地后基本用不上，仅为极恶劣光照场景留后手。

### 5.2 路线二【最推荐的算法升级】稀疏光流方向判断

把"有没有动"升级为"有没有**持续向下**动"：

- 每个 ROI 内仅对 50~100 个角点跑 Lucas-Kanade 稀疏光流，计算开销可忽略；
- 水的矢量场具备**持续向下 + 时间稳定**的强特征，几乎免疫水平振动与阴影扫过；
- 横向收益：光流速度幅值是比"能量百分比"靠谱得多的**水量代理指标**；
- 实现亲和性：现有 `AnchorTracker` 已使用模板匹配思路，代码风格一脉相承，改造不陌生。

### 5.3 路线三【解锁水量分级】小 CNN 三分类器

仓库已具备完整 TensorRT 推理引擎与 YOLO 部署管线（`yolov8_trt_engine/`），这是一张现成的底牌：

- 裁一个 96x96 输入的 MobileNet 级小分类器，对每根管 ROI 输出三分类：**大流量 / 小流量 / 断流**；
- Jetson 上五路并发仅数毫秒；
- 视觉分类可学会水花纹理、泡沫形态、反光闪烁等帧差看不见的语义特征，**直接答出客户需求级的"水量分级"**；
- 代价：需采集现场数据标注一轮（现场实拍视频与演练素材已有积累）；
- 触发时机：客户明确提出"水量降到 50% 就要预警"类需求时启用。

### 5.4 路线四【工业祖传答案】物理传感器冗余

客观说明：精确计量水量，视觉永远打不过二十几元的流量开关 / 涡轮流量计。若现场允许管改，**视觉 + 物理传感器双通道互相校验**是无人值守机房应有的冗余结构。视觉的核心价值在于**非侵入、免维护、一台相机看六根管**——本职是"哨兵"，不是"水表"。

## 8. 引用算法伪代码速查（供改造时对照）

```text
# 每帧处理 (water_flow_analyzer.cpp :: process)
gray   = cvtColor(frame, GRAY)
blur   = GaussianBlur(gray, 5x5)
diff   = absdiff(blur, prev_blur)
mask   = threshold(diff, 12)              # >12 置白
for each pipe roi:
    E_inst = countNonZero(mask[roi]) / area(roi) * 100
    E      = 0.75 * E_inst + 0.25 * E     # EMA
    if E < threshold:
        dur = now - low_start
        dur >= 2.0s  -> ALARM(+飞书红卡, 需 now >= 8s 且距上次 > 60s)
        dur >= 0.5s  -> WARN
    else:
        low_start = 0; state = NORMAL
        if 曾 ALARM -> 飞书绿卡(需 now >= 8s)

# 抗抖 (AnchorTracker)
dx, dy = matchTemplate(anchor_region)     # 置信度 >= 0.65, 限幅 ±35px
dynamic_roi = base_roi + (dx, dy)
```
